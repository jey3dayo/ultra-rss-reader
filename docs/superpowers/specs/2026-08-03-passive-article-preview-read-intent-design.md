# Passive Article Preview Read Intent Design

## Summary

起動時やスコープ切替時に先頭記事を自動表示しても、その表示だけでは記事を既読にしない。
自動表示を `preview`、記事行のクリックやキーボード操作による明示選択を `reading` として区別し、
既存の自動既読タイマーは `reading` へ移行した時点で開始する。

## Problem

起動時は保存済みアカウントの `未読` スマートビューを復元する。
記事ビューは先頭の未読記事を自動選択して本文を表示するが、現在はこの自動選択とユーザーによる記事選択を区別していない。

既定の `after_reading` は `after_0_3s` であるため、アプリを起動して先頭記事が表示されただけで、
その記事が 0.3 秒後に既読になる。本文をすぐ読める点は維持したい一方、単なる自動表示を読書意思として扱うのは早すぎる。

同じ問題は起動時だけでなく、未読、フィード、フォルダ、タグなどの切替後に先頭記事が自動表示される場合にも起こる。

## Goals

- 自動表示された記事本文はこれまでどおりすぐ読める
- 自動表示だけでは未読状態を維持する
- 記事行のクリック、キーボード選択、前後記事への移動を読書開始として扱う
- 読書開始後は既存の `after_reading` 設定をそのまま適用する
- 手動の既読・未読切替と未読ビュー内の選択記事保持を変えない

## Non-goals

- 本文のクリックやスクロール量から読了を推測する
- 新しい既読設定や画面上の状態表示を追加する
- 既読同期、未読件数、記事保持、履歴記録の契約を変更する
- `after_reading` の既定値や選択肢を変更する

## Considered Approaches

### 1. Preview と reading を明示的な状態として保持する

選択記事に対するユーザーの関与状態を UI store に保持する。
自動着地は `preview`、明示選択は `reading` を設定し、自動既読処理は `reading` の場合だけ動作する。

この案は起動時と各スコープ切替を同じ規則で扱え、表示中と同じ記事を改めて選択した場合も状態遷移として表現できる。

### 2. 起動後の最初の自動既読だけを抑制する

起動済みフラグで最初の mutation を止める案。
変更量は小さいが、フィードやスマートビュー切替による自動表示には適用できず、起動経路ごとの例外が増える。

### 3. 自動既読までの時間を延ばす

既定値を数秒へ延ばす案。
誤既読を減らすだけで、操作しなくても最終的に既読になる問題は解消しない。

採用案は 1 とする。

## Design

### Article engagement state

選択記事の表示状態として、次の 2 値を UI store が所有する。

- `preview`: 自動着地によって本文を表示しているが、ユーザーは記事を明示選択していない
- `reading`: ユーザーが記事を明示選択または前後移動した

記事が未選択のときは engagement に意味を持たせない。
記事選択の解除、アカウント変更、スコープ変更では、以前の記事の `reading` 状態を次の記事へ持ち越さない。

`selectArticle` は選択理由を受け取れるようにする。
既存の明示選択呼び出しを安全側で維持するため、理由を省略した場合は `reading` とする。
同じ記事 ID がすでに `preview` で表示されていても、明示選択されたら `reading` へ更新する。

### Preview entry points

先頭記事をプログラムから自動選択する経路だけが `preview` を指定する。

- 起動時に復元された未読スマートビューの先頭記事
- 未読、スター、最近の記事などのスマートビュー切替後の先頭記事
- フィード、フォルダ、タグ切替後の先頭記事
- フィード着地処理が取得した先頭記事

自動表示でも、現在と同じ選択行の強調と本文表示を維持する。新しいバッジや説明文は追加しない。

### Reading entry points

次の操作は `reading` とする。

- 記事行をクリックする
- キーボードで記事を選択し、本文へ進む
- 前後の記事へ移動する
- コマンドパレットから記事そのものを直接選択する

フィードを選択した結果として先頭記事が開く場合は、記事そのものの直接選択ではないため `preview` のままとする。
本文ペインのクリックやスクロールだけでは `reading` へ移行しない。

### Auto-mark behavior

`useArticleAutoMark` は engagement が `preview` の間、既読 mutation と遅延タイマーを開始しない。

同じ記事が `reading` へ移行したら、その時点を起点として現在の `after_reading` を適用する。

- `never`: 自動既読にしない
- `immediately`: 移行直後に既読化する
- `after_0_3s`、`after_0_5s`、`after_1s`: 移行後に指定時間だけ待つ

記事変更、アカウント変更、表示解除がタイマー完了前に起きた場合は、既存の世代管理と cleanup で mutation を防ぐ。
mutation 失敗時の toast、未読ビューでの選択記事保持、手動で未読へ戻した後の自動既読抑制も既存挙動を維持する。

## State Transitions

1. アプリ起動またはスコープ切替で先頭記事を自動表示する
2. 選択記事を `preview` として保持する
3. 自動既読は開始せず、記事は未読のまま本文を表示する
4. ユーザーが記事行を選択するか前後移動する
5. 選択記事を `reading` へ更新する
6. `after_reading` に従って自動既読を実行する

自動表示された本文を読むだけで明示選択しなかった場合、その記事は未読のまま残る。

## Verification

振る舞いに直結する次のケースを検証する。

- 未読スマートビューの先頭記事が自動表示されても、設定時間経過後に既読 mutation が発生しない
- フィードなどの切替で先頭記事が自動表示されても未読を維持する
- `preview` 中の同じ記事行をクリックすると `reading` へ移行し、設定時間後に既読になる
- キーボードでの選択と前後移動は `reading` として扱われる
- `after_reading = never`、手動既読切替、手動で未読へ戻した後の抑制は従来どおり動作する
- スコープ変更や記事選択解除で以前の `reading` 状態が次の記事へ漏れない

実装時は関連する store と記事ビューの focused test を実行し、DOM/React 挙動を含むため
`mise run test:unit:dom`、通常の完了ゲートとして `mise run check` を実行する。
