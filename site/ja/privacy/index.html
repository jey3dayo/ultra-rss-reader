Ultra RSS Reader のプライバシー方針

Ultra RSS Reader が扱うデータの保存先、外部との通信、および現在のフィードコンテンツ方針の要点をまとめています。

サポートページ support@jey3dayo.net

保存されるデータ

アプリが扱うデータは、原則としてお使いの端末内に保存されます。

  • 認証情報

    FreshRSS のパスワードやトークン、任意の Cloudflare Access 認証情報は、既定で SQLite ではなく OS のキーリングに保存されます（設定からローカルファイル保存に切り替えることもできます）。

  • ローカルデータ

    購読フィードや取得した記事、既読・スター状態などは、端末内の SQLite データベースに保存されます。

  • 記事本文

    本文表示では、Rust 側でサニタイズした HTML のみを描画します。

通信について

本文表示と Webプレビューでは、プライバシー上の挙動が異なります。

  • 本文表示

    サニタイズ済みの記事を開いた場合でも、本文内に含まれる配信元ホストのリモート画像を読み込むことがあります。

  • Webプレビュー

    Webプレビューはアプリ内の埋め込みブラウザとして動作するため、配信元の Web ページを直接開く場合と同様に通信が発生します。

  • 通信先へ伝わる情報

    リモート画像やページを読み込む際、IP アドレス、ユーザーエージェント、アクセス日時などが配信元や第三者ホストへ伝わることがあります。

現在の方針

ご利用前に把握しておいていただきたい、現在の設計上の前提です。

  • 互換性重視のポリシー

    現在、記事コンテンツの表示においては読みやすさと表示互換性を優先する方針を採っています。

  • 保護している領域

    アプリ自身のスクリプト実行は 'self' に制限し、本文表示にはサニタイズ済みの HTML のみを使用します。

  • 現時点で保証していないこと

    記事を開いた際に、第三者ホストへの通信が一切発生しないことは現在の仕様では保証していません。

今後の方向性

プライバシー保護を強化する際も、表示互換性とのバランスを見ながら段階的に進めます。

  • 一律遮断を行わない理由

    リモート画像や埋め込み要素を一度にすべて遮断すると、記事の可読性やプレビューの互換性を大きく損なうおそれがあるため、急激な全面制限は行っていません。

  • 段階的な見直し

    プライバシー機能の強化は段階的に進め、本文表示と Webプレビューの設定は分けて管理できる形を目指しています。

  • 変更前の検証

    制限を強める変更を行う際は、本文表示・Webプレビュー・配布用パッケージビルドでの動作確認を前提とします。
